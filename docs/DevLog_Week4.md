## 주요 기술 결정
- 로직과 화면 분리: 그리드 계산(놓기 가능 여부, 빈 자리 찾기, 합치기, 예약)은 MonoBehaviour가 아닌 일반 클래스 InventoryGrid에 두고, InventoryWindow는 그리기와 입력 전달만 함
- 아이템은 (ID, 개수)로만 보냄: ScriptableObject는 전송할 수 없으므로 ItemDatabase로 찾음. 상자 안 아이템은 "상자의 몇 번째 항목"으로 식별
- 상자 내용물: 맵에 미리 배치한 씬 오브젝트(PhotonView)라 모든 화면이 같은 상자를 가짐. 마스터가 시작할 때 내용물을 정해 모두에게 보내고, 꺼낼 때마다 "몇 번 항목이 빠짐"만 보냄. 꺼낸 항목은 지우지 않고 개수 0으로 남겨 번호가 밀리지 않게 함
- 상자와 시체는 같은 코드: 내용물 목록(LootContainer, Inventory 모듈)과 동기화(LootContainerSync, Network 모듈)를 나눠, Inventory 모듈은 Photon을 모름. 5주차 플레이어 시체도 그대로 재사용
- 땅의 아이템: 마스터가 InstantiateRoomObject로 생성(생성 데이터에 아이템 ID와 개수)하고 주우면 PhotonNetwork.Destroy. 중도 참가자는 생성 정보를 자동으로 받고, 지워진 것은 받지 않음
- 요청 검증: 마스터가 아닌 사람의 요청은 요청자 캐릭터의 PhotonView ID로 주인인지, 거리 4m 안인지 확인. 버리기는 마스터 사본에 그 아이템이 있는지도 확인
- 입력 막기: PlayerInputGate 하나가 막는 이유(인벤토리, 채팅)별 인스펙터 목록으로 입력 컴포넌트를 끔. 입력 담당 코드는 거의 고치지 않고 추가만 함
- 상호작용: IInteractable(우선순위, 길게 누를 시간, 안내 문구, 실행)을 Core에 두고 상자·시체·땅의 아이템이 구현. 7주차 부활도 같은 인터페이스로 추가 가능
- 채팅 보낸 사람 이름: 메시지에 이름을 넣지 않고 받는 쪽에서 info.Sender.NickName으로 붙여 위조할 수 없게 함

## 해결한 기술 문제

### 두 명이 같은 아이템을 동시에 꺼낼 때 중복 획득
- 문제: 두 화면에서 같은 상자의 같은 항목을 거의 동시에 꺼내면 둘 다 받을 수 있음. 또 승인을 받은 뒤에 내 인벤토리에 자리가 없으면 처리할 방법이 없음
- 해결: 요청하기 전에 내 인벤토리에 자리를 먼저 예약(같은 아이템의 덜 찬 묶음에 먼저, 남은 개수는 빈 칸)하고 마스터에 요청. 마스터는 항목이 아직 있을 때만 승인하므로 먼저 도착한 요청만 성공. 나중 요청은 거절되어 예약을 되돌림. 예약 중인 칸은 흐리게 보이고 옮길 수 없음
- 배운 점: "승인 후에 자리를 찾는" 순서보다 "자리를 잡고 승인을 받는" 순서가 실패 경우를 줄인다

### 부모 클래스를 바꾸면 기존 무기 에셋 값이 사라질 수 있음
- 문제: WeaponData가 ItemData를 상속하도록 바꾸면서 ID와 이름 필드를 부모로 옮기고 이름도 바꿔야 했음. Unity는 필드 이름으로 값을 저장하므로 이름이 바뀌면 값이 비게 됨
- 해결: 새 필드에 FormerlySerializedAs로 예전 이름(_weaponId, _weaponName)을 지정해 기존 에셋 값을 그대로 읽게 함. 적용 후 무기 3종 에셋의 ID와 이름을 눈으로 확인
- 배운 점: 직렬화 필드 이름을 바꿀 때는 기존 에셋이 있는지 먼저 확인한다

### 적 시체의 상호작용 콜라이더가 사망 처리와 섞임
- 문제: 적이 죽으면 EnemyDeath가 탄 판정 콜라이더를 끄는데, 같은 오브젝트에 상호작용 콜라이더를 두면 함께 꺼지거나 살아 있는 동안에도 상호작용 대상이 됨
- 해결: 상호작용 콜라이더를 Interactable 레이어의 자식 오브젝트로 분리하고 프리팹에서는 꺼 둠. 시체가 되면 EnemyCorpseLoot가 켬
- 배운 점: 역할이 다른 콜라이더는 오브젝트를 나누면 켜고 끄는 처리가 서로 간섭하지 않는다

### 인벤토리 창을 닫으면 다시 열리지 않을 수 있음
- 원인: 창을 여닫는 스크립트가 붙은 오브젝트 자체를 끄면 Update가 멈춰 Tab 입력을 받을 수 없음
- 해결: 화면 스크립트는 부모에 두고, 켜고 끄는 Root는 자식으로 분리. 인벤토리, 상자, 안내, 채팅 화면 모두 같은 구조
- 배운 점: "끄는 대상"과 "끄는 주체"는 같은 오브젝트에 두지 않는다

### 탄약 개수가 보이지 않고 합쳐지지 않음
- 원인: 아이템 에셋의 Max Stack 기본값이 1로 남아 있었음. 코드는 최대 스택이 1보다 클 때만 개수를 표시하고, 가득 찬 묶음에는 합치지 않음
- 해결: 탄약과 소모품 에셋의 Max Stack을 지정
- 배운 점: 코드가 아니라 데이터 설정 문제일 수 있다. 증상 두 개가 한 원인으로 설명되면 그 원인부터 확인한다

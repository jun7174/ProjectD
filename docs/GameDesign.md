## 1. 코어 루프와 게임 규칙
 
### 1-1. 레이드 흐름 [확정]
 
로비 → 장비 선택 → 방 만들기 또는 방 목록에서 참가 → 출격(진행 중인 레이드에 합류 가능) → 파밍과 전투 → 탈출 → 정산
 
### 1-2. 레이드 제한 시간 [확정]
 
- 제한 시간 15분
- 초과 시 즉시 사망 처리가 아니라, 게임 안의 요소로 자연스럽게 사망을 유도 (웨이브 + 디버프 조합)
| 구간 | 처리 | 임시 테마 연출 |
|---|---|---|
| 남은 3분 | 경고 표시, 소규모 적 웨이브 시작. 시간이 지날수록 강해짐. 동시 활성 적 상한 안에서만 스폰 | 기지 봉쇄 단계 상승, 보안 로봇 증원 |
| 시간 초과 후 | 웨이브 유지 + 점점 강해지는 지속 데미지. 회복템 효과 무효. 반드시 사망으로 끝남 | 환기 시스템 정지, 독가스 유입 |
 
- 웨이브 스폰은 탈출 카운트다운 중 적 추가 출현과 같은 스폰 기능으로 구현
- 지속 데미지는 회피와 무관하므로 피격자 확인 없이 마스터가 바로 적용
- 일정이 밀리면 웨이브만 제거하고 디버프만 유지
### 1-3. 사망 패널티 [확정]
 
- 기본 규칙은 사망 시 소지품 전부 손실
- 업그레이드를 통해 일부 슬롯을 보호하는 완화 방식을 열어갈 수 있음
- 보호 슬롯에 넣은 아이템은 사망해도 사망자가 그대로 유지
### 1-4. 팀원 사망 처리 [확정]
 
생존 → 다운 → 사망으로 이어지는 단계형 구조.
 
| 단계 | 규칙 |
|---|---|
| 생존 | 일반 상태 |
| 다운 | 체력이 0이 되면 진입. 제한 시간 안에 팀원이 상호작용하면 부활 |
| 사망 | 다운 제한 시간 초과 시 진입. 시체가 루팅 상자가 되어 팀원이 소지품 회수 가능 |
 
세부 규칙
 
- 회수한 아이템은 가지고 나간 사람의 소유. 원주인에게 돌려주는 로직은 만들지 않음
- 보호 슬롯 아이템은 시체에 남지 않음
- 혼자 플레이할 때는 다운 상태 없이 즉시 사망
- 다운된 플레이어는 부조리한 상황 방지를 위해 스스로 사망을 선택할 수 있음 (X 길게 누르기, 일반 사망과 동일 규칙)
- 사망한 플레이어는 살아 있는 팀원 시점으로 관전
- 다운, 부활 성공, 사망 판정은 모두 마스터 클라이언트가 결정
- 부활 상호작용은 마스터 클라이언트가 거리와 지속 여부를 검사하고, 부활시키는 사람이 피격되거나 이동하면 취소
세부 수치 (플레이테스트로 조정)
 
- 다운 제한 시간 30초
- 부활은 F 3초 길게 누르기
- 다운 중 30% 속도로 기어가기 가능
- 부활 직후 체력 30%
구현 순서
 
- 시체 회수(루팅 상자 재사용)를 먼저 구현하고, 다운과 부활은 루프 완성 후 추가
추후 확장 후보
 
- 혼자 플레이용 자가 부활 아이템
### 1-5. 탈출 규칙 [확정]
 
기본 규칙
 
- 전원 함께 탈출 + 카운트다운 방식
- 살아있는 팀원 전원이 같은 탈출구에 도착해야 카운트다운 시작
- 카운트다운이 끝나면 전원이 함께 탈출
세부 규칙
 
- 다운된 팀원도 살아있는 것으로 간주. 탈출구 밖에 다운자가 있으면 카운트다운 시작 불가
- 카운트다운은 구역 이탈 시에만 리셋. 피격으로는 취소되지 않음
- 카운트다운 중 구역 안에서 다운된 팀원도 함께 탈출
- 카운트다운 길이 10초 내외 (추후 조정 가능)
- 탈출 성공 시 마스터 클라이언트가 성공을 알리고, 씬 전환 전에 각 클라이언트가 로컬 저장
- 레이드 종료 조건: 탈출 성공, 전원 사망
- 혼자 플레이와 마지막 생존자 1인도 같은 규칙으로 동작
- 남은 3분 경고 이후와 탈출 카운트다운 중에는 새 참가자가 들어올 수 없음 (9번 중도 참가 참고)
추후 확장 후보
 
- 카운트다운 중 적 추가 출현 연출 (1-2 웨이브 스폰 기능 재사용)
### 1-6. 레이드 간 경제 [확정]
 
기본 구조
 
- 상점에서 판매하고 구매하는 방식
- 기본 재화는 돈이며, 획득품 판매로 얻음
- 특수 물품과 일부 업그레이드는 필드에서 얻는 특정 아이템으로 교환
- 데스 스파이럴 방지를 위해 무료 기본 장비 지급
세부 규칙
 
- 상인 1명, 한 화면에 판매, 구매, 교환, 업그레이드 배치
- 구매 목록 고정: 탄약, 회복템, 무기 2~3종
- 돈은 플레이어별 로컬 저장, 팀원 간 송금 없음
- 교환 재화는 전용 아이템 2~3종
- 교환 재화는 위험 구역, 보스, 희귀 상자에서 주로 획득
- 교환 재화도 그리드 칸을 차지하며 탈출해야 확보
- 교환 재화는 낮은 가격에 판매 가능
- 보호 슬롯 업그레이드는 1단계 돈, 2단계 교환 재화 필요
- 교환 전용 특수 물품은 고유 역할의 고급 무기 1종 (예: 저격형 정밀 소총)
- 무료 기본 장비: 무기 슬롯이 빈 채로 출격하면 기본 권총과 소량 탄약 자동 지급, 판매 불가
- 가격과 교환 조건은 ScriptableObject에 비용 목록(재화 종류 + 수량)으로 정의해 돈과 아이템 비용을 같은 구조로 처리

## 2. 플레이어 조작과 카메라 [확정]
 
| 항목 | 내용 |
|---|---|
| 키 배치 | WASD 이동, Shift 달리기, Space 회피, 좌클릭 사격, 우클릭 정밀 조준, V 근접 공격, R 재장전, F 상호작용, Tab 인벤토리, M 전체 지도, 1·2 무기 교체, 3~5 퀵슬롯, 다운 중 X 길게 눌러 자율 사망, Esc 메뉴, Enter 채팅 |
| 상호작용 규칙 | F 하나로 통합. 가장 가까운 대상 하나에 강조 표시, 우선순위 부활 > 상자 > 아이템. 줍기는 짧게, 상자 열기와 부활은 길게 누르기 |
| 키 변경 기능 | 1차 범위 제외. 입력은 Input Action 단위로 처리해 추후 UI만 추가 가능하게 |
| 이동 단계 | 걷기(기본) + 달리기(Shift) 2단계. 앉기 없음. 달리기는 소음 큼, 걷기는 작음 |
| 달리기 중 사격 | 불가. 사격 키나 우클릭을 누르는 동안 달리기 해제. 떼면 Shift를 누르고 있는 한 다시 달림 |
| 스태미나 | 달리기, 회피, 근접 공격에 소모. 로컬 전용, HUD 막대 표시. 0이 되면 달리기 키를 뗐다가 다시 눌러야 달리기 가능. 스태미나 회복 아이템으로 즉시 회복 가능 |
| 회피기 | 스태미나로 사용 제한 (별도 쿨다운 없음) |
| 회피 무적 | 있음. 피격자 최종 확인 방식 (9-1 참고) |
| 회피 세부 | 무적은 회피 앞부분 일부(0.2~0.3초)에만 적용. 방향은 이동 입력 방향(입력 없으면 바라보는 방향). 회피 중 사격·조준 불가. 스태미나가 회피 1회 비용보다 적으면 회피 불가 |
| 조준 방식 | 항상 마우스 방향 + 우클릭 정밀 조준 (탄퍼짐 감소, 이동 감속, 카메라 오프셋) |
| 카메라 | 각도 고정(정면 시점, 좌우 0도, 아래로 약 55도), 줌 없음(고정 거리). 우클릭 조준 시 마우스 방향으로 카메라 오프셋. 이동 입력은 월드 기준(W = 월드 +Z = 화면 위쪽) |
| 게임패드 | 현재 미지원. New Input System 기반으로 추후 지원 가능하도록 확장성만 확보 |
| 애니메이션 구조 | 플레이어 하나에 Animator Controller 하나, Base Layer 하나만 사용. 블렌드 트리 없이 상태 하나에 클립 하나, 한 번에 하나의 클립만 재생. 뒤로 이동할 때는 이동 클립을 거꾸로 재생. 재장전 클립은 멈춰 있을 때만 재생하고, 재장전 시간 동안 반복 |

## 3. 전투 [확정]
 
### 3-1. 판정과 명중
 
| 항목 | 내용 |
|---|---|
| 판정 방식 | 플레이어 총기와 적 공격 모두 투사체 |
| 투사체 네트워크 처리 | 탄마다 네트워크 오브젝트를 생성하지 않음. 쏜 쪽이 한 번 쏠 때 RPC 하나로 무기 ID와 방향 목록만 보내고(시작점은 보내지 않음), 받는 쪽은 화면 속 그 캐릭터의 총구 위치에서 풀링된 시각용 탄을 재생. 플레이어 탄의 명중은 쏜 클라이언트가 판정 후 마스터 검증, 적 탄은 마스터가 시뮬레이션하고 피격자 최종 확인. 판정용 투사체와 시각용 투사체는 ProjectileLauncher의 Launch(판정용)와 LaunchVisualOnly(시각용, 데미지 없음)로 구분. 판정용의 명중 처리는 IHitHandler로 분리해, 방 밖(Sandbox)은 바로 데미지(DirectDamageHitHandler), 방 안은 마스터 보고(PlayerHitReporter) |
| 투사체 구현 주의 | 오브젝트 풀링 필수. 빠른 탄의 벽·대상 관통 방지를 위해 프레임 간 이동 구간을 레이캐스트로 검사 |
| 탄퍼짐 | 있음. 각도는 조준 방향에서 한쪽으로 최대 몇 도 벗어나는지로 정의. 쏘지 않으면 누적 탄퍼짐이 서서히 회복. 우클릭 정밀 조준 시 감소 |

| 부위 판정 | 미포함 |

| 격자 | 가로 1m 단위(벽 조각 폭), 벽 높이 3m. Scene 뷰 Grid Snapping 이동 단위 1 |

| 레이어 | 벽·바닥·지면·엄폐용 큰 구조물: `Environment` / 천장: `Roof` / 플레이어: `Player` / 적: `Enemy` |
| 벽 | 우리 프리팹 변형(`Assets/Prefabs/Environment/Walls/`): Environment + Occluder(Transparent, M_OccluderTransparent) |
| 천장 | 우리 프리팹 변형(`Assets/Prefabs/Environment/Roofs/`): Roof + Occluder(ShadowsOnly). **방 하나에 천장 한 장**, Scale로 방 크기에 맞추고 가장자리는 벽 위에 살짝 걸침 |
| 바닥 | Synty 원본, Environment |
| 큰 구조물(컨테이너, 자재 더미, 차량, 기둥 등) | 캐릭터를 가릴 수 있는 높이(약 1.5m 이상)면 Occluder(Transparent) 추가. 엄폐물로 쓰므로 콜라이더 유지, Environment |
| 작은 장식 소품 | 탄과 이동에 영향이 없게 콜라이더 제거(씬 배치본에서 제거, Synty 원본은 수정하지 않음). 레이어는 Default |
| 문·통로 | 폭 최소 2m (플레이어와 적 NavMeshAgent가 함께 지나갈 수 있게) |
| 방 | 최소 5×5m (천장 조각 한 장 크기) |
| 숨김 단위 | 천장 한 장 = 방 하나. 방 B는 들어가기 전까지 덮여 있음 |
| NavMesh | NavMeshSurface 하나로 맵 전체를 굽는다. Include Layers: Environment만, Use Geometry: Physics Colliders. Roof는 제외(지붕 위에 길이 생기지 않게). Scene 뷰 Gizmos를 켜야 보인다. 맵을 고치면 다시 굽는다 |
| 하이어라키 | `Map` 아래에 `Ground`, `Zone_Outer`, `Zone_Middle`, `Zone_Center`, 구역 안에 `Building_이름`(Walls, Roofs, Floor 정리용 자식), `Props`. 지점은 `Map/Points` 아래에 `StartPoints`, `ExtractionPoints`, `EnemySpawns` |
| 맵 위치 | Raid 씬에 직접 제작. Sandbox는 작은 테스트용으로 유지 |
| Static 설정 | 3주차에는 켜지 않음. 8주차 성능 측정 때 Occluder와 함께 쓸 수 있는지 확인 후 결정 |

## 9. 멀티플레이와 네트워크 [확정]
 
| 항목 | 내용 |
|---|---|
| 네트워크 솔루션 | Photon PUN 2 (숙련도와 일정 고려. LTS 모드라는 점은 기술 문서에 선택 이유와 함께 명시) |
| 권한 구조 | 마스터 클라이언트가 게임 상태 권한 |
| 최대 인원 | 4인 (1인 싱글 플레이 가능) |
| 플레이어 이름 | Boot 씬에서 입력. 앞뒤 공백 제거 후 1~12자, 마지막 이름을 저장해 다음 실행 때 미리 채움, 중복 허용(구분은 UserId) |
| 매칭 방식 | 공개 방 목록. 로비에서 열린 방 목록을 보고 참가하거나 새 방을 만듦. 표시 이름은 "닉네임의 방"(방 속성), 실제 방 이름은 중복 없는 고유 문자열. Photon 기본 로비를 사용하고, 바뀐 방만 오는 목록을 딕셔너리에 반영해 전체 목록을 직접 보관 |
| 혼자 플레이 | PUN 2 오프라인 모드 사용 (인터넷 없이 플레이 가능). 오프라인 방은 목록에 보이지 않음. 온라인으로 방을 만들어 혼자 플레이하는 것도 가능 |
| 마스터 클라이언트 이탈 | 세션 종료 + 레이드 무효 (출격 장비 반환, 획득품 없음). 방을 만든 사람이 나가면 중도 참가자를 포함한 전원의 레이드가 끝남. 새 마스터가 된 클라이언트가 방을 닫고(목록에서도 숨김) 전원이 나가 Lobby로 이동 |
| 레이드 나가기 | Lobby로 이동 (혼자 플레이는 오프라인 모드를 끄고 다시 접속해야 하므로 Boot로 이동) |
| 중도 참가 | 허용. 레이드 진행 중에도 방은 목록에 남고 4명 미만이면 참가 가능. 남은 시간은 방 기준 하나. 남은 3분 경고 이후와 탈출 카운트다운 중에는 마스터가 방을 닫음(목록에는 참가 불가로 표시). 3분 경고 전에 카운트다운이 리셋되면 다시 엶. 레이드가 끝나면 방을 닫음 |
| 재참가 제한 | 같은 레이드에서 나간 플레이어(사망, 탈출, 끊김)는 그 방에 다시 들어올 수 없음. 나간 플레이어 목록을 방 속성에 저장 |
| 중도 참가자 상태 동기화 | 계속 동기화되는 값은 그대로 받고, 한 번 일어난 일(적 사망, 상자 열림, 주운 아이템 등)은 참가 시점에 마스터가 현재 상태를 보냄. 각 기능의 완료 조건에 "중도 참가자에게도 같은 상태가 보임" 포함 |
| 일반 클라이언트 연결 끊김 | 사망과 동일 처리. 마스터가 아이템 목록 사본으로 끊긴 위치에 시체 생성, 팀원 회수 가능. 끊긴 플레이어는 "살아있는 전원"에서 제외 |
| 채팅 | 레이드 방 안에서만 동작 (로비 채팅 없음). 메시지는 RPC로 방 전원에게 전송하고 보낸 사람 이름은 닉네임. Enter로 입력창 열기, Enter로 보내기, Esc로 취소. 입력 중에는 이동·사격 등 게임 입력을 막음. 최대 60자, 화면 왼쪽 아래에 최근 6줄 표시, 일정 시간 뒤 흐려짐. 입장·퇴장 알림 표시. 중도 참가자는 들어오기 전 메시지를 받지 않음. 혼자 플레이(오프라인)에서는 채팅창을 숨김 (2026-11-19 추가) |
| 테스트 환경 | ParrelSync(Clones Manager)로 에디터 2개 테스트 + 매주 한 번 실제 빌드로 PC 2대 테스트 |

## 10. 기술 아키텍처
 
| 항목 | 상태 | 내용 |
|---|---|---|
| Unity 버전 | [확정] | 6000.3.10f1 (Unity 6.3)으로 고정, 개발 중 업그레이드 금지. PUN 2 임포트와 접속 확인 완료 |
| 렌더 파이프라인 | [확정] | URP |
| 입력 | [확정] | New Input System. Input Actions 에셋에서 C# 클래스 자동 생성(Generate C# Class)해 입력 담당 클래스가 읽음. 길게 누르기는 에셋 Interactions 대신 코드에서 누른 시간 측정. 게임패드·키 변경 확장 대비 |
| 캐릭터 이동 | [확정] | CharacterController. 팀원끼리는 레이어 충돌 표로 충돌 없음. 적과 플레이어는 서로 막힘(Player, Enemy 레이어 충돌). NavMeshAgent는 플레이어를 밀지 않음 |
| 카메라 | [확정] | Cinemachine 3 (Follow, World Space, Rotation Control 없음). 카메라 타깃은 플레이어의 자식 오브젝트로 두고 조준 오프셋 시 이동, Impulse로 화면 흔들림, 추적 대상 교체로 관전 |
| 레벨 프로토타이핑 | [확정] | 그레이박스 생략, 3주차부터 Synty 에셋으로 맵 제작. ProBuilder는 필요한 부분 보조로만 사용 (2026-11-06 변경) |
| Assembly Definition | [확정] | 사용하지 않음. 의존 방향은 네임스페이스 규칙과 통신 원칙으로 관리하고 기술 문서에 의존 방향 그림으로 표현 |
| 모듈 의존 방향 | [확정] | Combat은 Player를 참조할 수 있지만 Player는 Combat을 참조하지 않음. 전투 입력은 PlayerInputReader와 분리해 WeaponInputReader가 읽음. 모든 모듈은 Core를 참조할 수 있음. Network는 Player, Combat, AI, Data, Core를 참조할 수 있고 Player, Combat, AI는 Network를 참조하지 않음(오프라인 Sandbox에서 그대로 동작). AI는 Core, Data만 참조하고 플레이어는 EnemyTarget과 소음(NoiseSystem)으로만 앎. UI는 Network의 이벤트를 구독하고 AI의 상태 값을 읽을 수 있음. World는 Core만 참조하고 다른 모듈을 모름 |
| 상수와 열거형 | [확정] | Core/Define 폴더에 모음. 열거형은 Enum.cs 한 파일, 애니메이터 파라미터·셰이더 속성은 용도별 정적 클래스(AnimatorParams, ShaderPropertyIds 등)에 해시/ID로 정의 |
| 애니메이션 | [확정] | 리그는 Generic, 에셋 팩에 포함된 클립만 사용. 정수 파라미터 State 하나와 MoveDirection(앞 1, 뒤 -1)으로 제어. Any State에서 각 상태로 전환(조건은 State 값 하나, 전환 시간 0). 재생할 상태는 PlayerAnimationController가 우선순위로 결정하고, 사격·재장전 정보는 Combat의 WeaponAnimationBridge가 전달. 상태 번호는 Enum.cs의 PlayerAnimState. 예외로 회피 시작 시에만 Animator.Play로 회피 상태를 처음부터 재생 (연속 회피 대응). 상태 이름 해시는 Core/Define/AnimatorStates.cs. 네트워크 동기화는 계산된 State 번호, 뒷걸음 여부, 회피 횟수만 전송하고(PlayerAnimationSync), 남의 캐릭터는 받은 값을 그대로 재생 |
| 씬 구성 | [확정] | Boot(초기화, 저장 로드, 이름 입력, Photon 연결) → Lobby(방 목록, 창고, 상점, 정산) → Raid. 방에 들어간 사람(방장, 중도 참가자, 혼자 플레이)은 각자 OnJoinedRoom에서 PhotonNetwork.LoadLevel로 Raid 씬을 불러옴. LoadLevel이 불러오는 동안 메시지 처리를 멈추므로, 중도 참가자가 받는 기존 캐릭터 생성 정보가 Raid 씬에서 처리됨. AutomaticallySyncScene은 사용하지 않음 (대기실이 없고 레이드 종료 시 각자 나가므로 불필요) |
| 프로젝트 코드명 | [확정] | ProjectD (덕르코프의 D, 기존 ProjectT 관례와 동일. 테마와 무관하게 유지) |
| 네임스페이스와 주석 규칙 | [확정] | ProjectD.Core, ProjectD.Network, ProjectD.Player, ProjectD.Combat, ProjectD.AI, ProjectD.Inventory, ProjectD.UI, ProjectD.Data, ProjectD.World(맵에 속한 기능: 실내 표현 등, 3주차 추가)로 구분. 주석은 한글 |
| 데이터 구조 | [확정] | ScriptableObject 대상: 아이템 계열, 무기, 무기 데이터베이스(ID로 찾기), 적, 루팅 테이블, 상점 목록(비용 목록 구조), 업그레이드, 밸런스 설정(다운 시간, 카운트다운, 인원 배율 등 수치 모음) |
| 시스템 간 통신 | [확정] | 같은 오브젝트 안에서는 직접 참조, 시스템 사이에서는 C# 이벤트. UI는 이벤트를 구독만 하고 게임 로직은 UI를 모르게. 단, 조준점처럼 매 프레임 바뀌는 값을 그리는 UI는 읽기 전용 값을 매 프레임 읽는 것을 허용. 싱글톤 매니저는 세션, 저장, 네트워크 정도로 제한. RPC 수신 메서드는 얇게 두고 실제 처리는 일반 메서드로 분리 |

| 디버그 도구 | [확정] | 초기부터 구현. 무적, 아이템 지급, 적 스폰, 즉시 탈출, 네트워크 지연 시뮬레이션 |

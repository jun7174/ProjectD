- 플레이어 피격: 피격자 최종 확인 방식의 회피 무적, 데미지 숫자, 임시 체력 표시, 체력 0 임시 처리(3초 후 회복)
- 인원별 적 체력 배율, 먼 적 휴면, 적 시체, 적 상태 중도 참가 동기화
- 머리 위 디버그 표시(상태 이름, 경계 게이지)와 시야 Gizmo
## 주요 기술 결정
- 실내 표현 감지: 건물마다 트리거를 두지 않고, 내 캐릭터의 OccluderProbe가 0.1초마다 카메라→캐릭터 SphereCast(가리는 벽)와 머리 위 Raycast(덮은 천장)로 찾음. 천장은 방마다 한 장으로 크기를 맞춰 "천장 한 장 = 방 하나"로 숨김 단위를 정함. 숨길 때 원래 sharedMaterials를 저장했다가 복구(materials는 복제본이 생겨 쓰지 않음)
- 적 상태 머신: 상태 클래스 패턴(IEnemyState의 Enter, Tick, Exit). 감지 이벤트에 따른 전환은 EnemyBrain이, 상태 안의 조건(도착, 사거리, 놓친 시간)은 각 상태가 판단. 공격 상태만 종류별(돌진, 점사)
- 모듈 의존: AI는 Core와 Data만 참조. 공격 결과는 EnemyWeapon 이벤트(근접 명중, 발사)로만 알리고, 탄 생성과 피격 신호는 Network의 EnemyAttackSync가 맡음. 그래서 AI는 Photon과 투사체 구현을 모름
- 동기화량 최소화: 위치는 PhotonTransformView, 그 외는 상태 byte, 경계 게이지 byte, 예고 여부 bool만 정기 전송
- 소음: 새 RPC 없이 마스터가 이미 받는 애니메이션 상태와 발사 이벤트로 소음을 만듦. 소음만으로는 게이지가 0.8까지만 차서 추적하지 않고 조사만 함
- 피격자 최종 확인: 마스터가 공격 번호와 데미지를 보관하고 피격자에게는 번호만 보냄. 피격자는 자기 화면 기준으로 무적 중이거나 무적이 끝난 지 0.1초 이내면 피함으로 답함. 데미지 값을 피격자가 바꿀 수 없고, 같은 번호는 한 번만 처리
- 투사체 풀: 런타임에 생성되는 적 프리팹은 인스펙터로 씬의 풀을 연결할 수 없어, 풀에 종류(Player, Enemy)를 두고 발사 담당이 같은 종류의 풀을 찾게 함
- 휴면: 휴면 중에는 photonView.Synchronization을 Off로 꺼서 전송을 멈춤. 깨우는 거리 25m와 재우는 거리 30m를 다르게 두어 경계에서 깜빡이지 않게 함
- 적 사망: 지우지 않고 시체로 남김(4주차 루팅 상자로 재사용). 체력 0은 모든 화면에서 같이 일어나므로 시체 처리도 각 화면이 직접 함
## 해결한 기술 문제
 
### 중도 참가 시 InvalidCastException으로 튕김
- 증상: 적이 있는 방에 나중에 들어가면 EnemySync.OnPhotonSerializeView에서 "Specified cast is not valid"가 나며 접속이 끊김
- 원인: 예고 여부 값을 추가하면서 보내는 순서(게이지, 상태, 예고)와 받는 순서가 어긋남. PhotonStream은 이름 없이 순서대로만 꺼내므로, bool 자리에서 byte로 바꾸려다 예외가 났고 메시지 처리 도중의 예외라 연결까지 끊김
- 해결: 보내는 줄과 받는 줄을 같은 순서로 나란히 두도록 파일 전체를 다시 정리. 원본과 복제 에디터가 같은 코드로 컴파일되었는지도 함께 확인
- 배운 점: OnPhotonSerializeView는 쓰기와 읽기가 한 쌍이다. 값을 하나 추가할 때는 두 곳을 같은 위치에 같이 고친다
### 휴면 중인 적과 시체가 중도 참가자에게 처음 생성 위치에 보일 수 있음
- 문제: 휴면이나 사망으로 위치 전송을 끄면, 나중에 들어온 사람은 정기 전송을 받지 못해 서버에 보관된 생성 위치에 적을 그리게 됨
- 해결
  - 휴면: 누가 들어오면 마스터가 0.3초 동안 전송을 다시 켜서 현재 위치와 상태를 한 번 보낸 뒤 끔
  - 시체: 마스터가 들어온 사람에게만 시체의 최종 위치와 회전을 RPC로 보냄. 체력 동기화(→ 사망 이벤트)와 이 RPC 중 어느 쪽이 먼저 와도 결과가 같도록, 시체 처리는 한 번만 하고 위치는 항상 마스터 값으로 덮어씀
- 배운 점: "한 번 일어난 일"은 정기 전송으로 전달되지 않는다. 참가 시점에 마스터가 보내는 구조와, 메시지 도착 순서에 상관없이 같은 결과가 나오는 처리가 함께 필요하다
### 적에게 데미지가 들어가지 않음
- 원인: 적 프리팹에 NetworkHealth가 없어 PlayerHitReporter가 맞은 대상을 네트워크 대상으로 찾지 못함
- 해결: 적 프리팹에 NetworkHealth 추가. 2주차 구조를 적에게 그대로 재사용할 수 있음을 확인
### NavMesh를 구웠는데 화면에 보이지 않음
- 원인: Scene 뷰 Gizmos가 꺼져 있었음
- 해결: Gizmos를 켜서 확인. 맵 제작 규칙(GameDesign 7-1)에 기록
### 필요 없는 경고가 콘솔을 채움
- 증상: 돌격형 적마다 "ProjectileLauncher를 찾지 못했습니다" 경고, 플레이어의 DamageFlash가 Renderer를 찾지 못함
- 원인: 돌격형은 탄을 쏘지 않아 Launcher가 필요 없음. 플레이어 몸의 렌더러는 루트가 아니라 자식 모델에 있음
- 해결: 경고를 점사형일 때만 출력. DamageFlash는 인스펙터에서 자식 렌더러 연결
- 배운 점: 경고는 실제로 필요한 경우에만 내야 진짜 문제가 묻히지 않는다

- 명중 처리: Combat에 IHitHandler 인터페이스, 구현은 DirectDamageHitHandler(Sandbox)와 PlayerHitReporter(Network) 두 개. Combat이 네트워크를 모르게 하는 의존성 역전

- 체력 동기화: 마스터가 정한 데미지를 RPC로 모두에게 보내 각자 Health.TakeDamage 실행. 기존 피격 이벤트(깜빡임, 숫자, 사망)를 그대로 재사용

## 해결한 기술 문제
 
### 중도 참가자에게 기존 플레이어가 보이지 않음
- 증상: 먼저 들어온 사람은 나중에 들어온 사람이 보이지만, 나중에 들어온 사람에게는 기존 플레이어가 전혀 보이지 않음
- 원인: Raid 진입을 PUN 씬 자동 동기화(AutomaticallySyncScene)에 맡겼더니, 중도 참가자가 방 입장 직후 받은 기존 캐릭터 생성 정보(서버에 보관된 Instantiate 이벤트)를 아직 Lobby 씬에서 처리함. 이어서 Raid 씬으로 교체되며 Lobby 씬과 함께 삭제됨
- 해결: 자동 동기화를 끄고 OnJoinedRoom 콜백 안에서 각자 PhotonNetwork.LoadLevel 호출. LoadLevel이 즉시 메시지 처리를 멈추고 씬 로드 후 재개하므로 생성 정보가 Raid 씬에서 처리됨. 함께 PhotonView Synchronization을 Unreliable로 바꿔, 멈춰 있는 플레이어도 위치를 보내 중도 참가자에게 현재 위치가 바로 보이게 함
- 배운 점: 네트워크 메시지 처리 시점과 씬 전환 시점을 맞춰야 한다. 중도 참가는 "보관된 이벤트를 어느 씬에서 받는가"까지 설계해야 한다
### Lobby에서 혼자 플레이를 누르면 Boot로 돌아감
- 증상: 혼자 플레이 버튼을 누르면 "서버 접속이 끊겼습니다 (DisconnectByClientLogic)" 경고 후 Boot 씬으로 이동
- 원인: 접속을 끊으면 OnDisconnected가 여러 컴포넌트에 차례로 호출된다. SoloPlayStarter가 먼저 받으면 그 콜백 안에서 오프라인 모드 전환 → 방 생성 → 방 입장(준비 플래그 해제)까지 한 번에 끝난다. 그 뒤 RoomListService가 OnDisconnected를 받을 때는 플래그가 이미 풀려 있어 진짜 끊김으로 판단하고 Boot를 불러옴
- 해결: OnDisconnected에서 준비 플래그와 함께 PhotonNetwork.OfflineMode도 확인
- 배운 점: Photon 콜백은 같은 이벤트를 여러 대상에게 차례로 호출하고, 콜백 안에서 다른 콜백이 연쇄로 일어날 수 있다. 바뀌기 쉬운 플래그보다 바뀌지 않는 근거로 판단한다
### 같은 프리팹에서 판정용 탄과 시각용 탄 구분
- 증상(예상): 내 캐릭터와 남의 캐릭터가 같은 프리팹이라 "데미지 줄지" 설정 하나로는 구분이 안 되어, 모든 화면에서 같은 탄이 각각 데미지를 주게 됨
- 해결: 설정 값을 없애고 Launch(판정용)와 LaunchVisualOnly(시각용) 두 함수로 나눔. 호출하는 쪽에서 의도가 이름으로 드러남
